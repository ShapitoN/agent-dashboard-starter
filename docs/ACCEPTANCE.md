# Приёмка и ограничения

## Проверка после переноса

1. Без входа чтение и запись Firestore запрещены; вход другим Google-аккаунтом не открывает данные владельца. Storage проверяется отдельно. Пустая закрытая панель не должна показывать чужие данные.
2. Backlog не запускается; тестовая To do создаёт файл только в указанной временной папке, читает его обратно и показывает доказательство, фактическую модель и результат.
3. Задача с вопросом попадает в Issue; вопрос виден в чате. Ответ владельца возвращает задачу в работу и передаётся в контекст. Не создаются повторные уведомления об одном событии.
4. Ручной выбор имеет приоритет. Смена исполнителя во время работы завершает старый процесс; прежний результат не перезаписывает новый. Изменение задания тоже инвалидирует старый результат.
5. Приёмка может принять, вернуть или задать вопрос. Reroute от Codex и Claude обрабатывается одинаково, кроме запрета при ручном выборе.
6. Второй worker не получает ту же аренду. Аварийно прерванная задача не повторяет внешние действия. При потере сети результат честно остаётся неопределённым до сверки.
7. Telegram-решение принимается только от владельца и для исходного сообщения. «Нельзя» блокирует действие. «Можно» относится к точному адресату, тексту и одной операции; повторный callback не создаёт повторную отправку. Проверять на собственном тестовом адресате.
8. Проверить PNG/JPEG-вложение и понятную ошибку для неподдерживаемого вложения. UI допускает SVG, но исполнитель его не поддерживает.
9. Учёт токенов не называет неизвестное нулём; это не деньги и не процент оставшегося лимита подписки.
10. Карта отражает только выбранные источники. Автозапуск проверен после нового входа в ОС, остановка действительно прекращает исполнитель. Сделана памятка и проверено восстановление безопасных тестовых данных.

## Что подтверждено при подготовке экспорта

Свежие результаты проверки записаны в [EXPORT_VERIFICATION.md](EXPORT_VERIFICATION.md). Исторические успешные live-тесты исходной установки не означают, что перенос работает на другом компьютере.

## Известные границы

- Это персональная система с одним владельцем, не сервис для множества изолированных пользователей.
- Доступ CLI к браузеру, MCP, почте и файлам проверяется отдельно. Вход в сайт не создаёт отсутствующее подключение инструмента.
- Специальный URI-handler зависит от ОС и desktop-клиента. Его запуск в исходной системе не был подтверждён полноценной ручной проверкой; HTTPS-ссылка — отдельный вариант.
- Широкие права CLI и переданный workspace требуют осознанного ограничения. Prompt с запретом отправок сам по себе не является системной песочницей.
- Некоторые UI-данные вставляются в HTML. Не открывать запись для недоверенных пользователей; перед командным/публичным использованием отдельно проверить экранирование HTML, URL и доступы.
- Совместимость потоковых событий и параметров CLI может измениться. Перед включением службы проверить реальный минимальный запуск и фактическую модель.
- Исходный test_fixes содержит необязательную проверку приватного исторического журнала. В экспорт он не включён, тест должен явно пропускаться.
- Отключение API-ключей в дочернем окружении не гарантирует бесплатную работу: тарификация и лимиты определяются вашей авторизацией и провайдером.
- Внешняя отправка через произвольный инструмент не имеет гарантии exactly-once. Неизвестный исход требует ручной сверки.
