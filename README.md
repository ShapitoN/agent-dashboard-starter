# Agent Dashboard + AgentDesk

Личная панель управления AI-агентами: карта связей, Kanban, проекты, планы, навыки и локальное выполнение задач через Claude Code / Codex CLI.

Это обезличенный снимок системы Антона от **21 октября 2026 года**, подготовленный для переноса и дальнейшей разработки с помощью AI. Исходники двух приложений собраны вместе. Это основа для адаптации, а не универсальный установщик: карта агентов, синхронизация рабочих документов и Telegram имеют индивидуальные интеграции.

## Что передать своей нейронке

Дайте ей ссылку на этот репозиторий и текст из **[START_HERE.md](START_HERE.md)**. Нейронке потребуется прочитать файлы репозитория: одна ссылка без доступа к содержимому не заменяет код. Можно скачать ZIP через GitHub → Code → Download ZIP и приложить файлы.

## Возможности

- Вход в веб-панель через Google, данные в Firestore, Hosting для статических файлов.
- Интерактивная карта агентов: поиск, фильтры, связи, проблемы, сведения об узлах.
- Kanban: Backlog → To do → In progress → Test / Done / Issue; описания, метки, изображения.
- Проекты, планы, навыки и состояние задач по расписанию.
- Sonnet классифицирует задачу, Python выбирает исполнителя и effort по явным правилам.
- Ручной выбор Claude Sonnet / Opus / Codex; замена во время выполнения останавливает прежний запуск.
- Исполнение CLI с журналом, идентификатором сессии, проверкой фактической модели, учётом сообщённых токенов.
- Приёмка результата, возврат и эскалация; переназначение от обоих провайдеров.
- Чат в карточке: вопрос → Issue, ответ владельца → повторный запуск.
- Транзакционная аренда очереди, heartbeat, проверка устаревших результатов, блокировки и ограничение параллелизма.
- Telegram: уведомления с дедупом и согласование одной конкретной отправки кнопками «Можно / Нельзя».
- Отдельное локальное окно AgentDesk для запуска запросов без Kanban.

## Состав

| Папка | Назначение |
|---|---|
| `dashboard/public` | Готовый frontend HTML/CSS/JS, без сборки Node |
| `dashboard/scripts/firebase_sync.py` | Исходный адаптер справочных данных; адаптировать перед запуском |
| `agentdesk` | Диспетчер, CLI-исполнители, приёмка, согласования, тесты |
| `reference/agent-graph` | Сборщик карты из исходной организации файлов; пример, требует переделки |
| `deploy` | Шаблоны двух systemd-служб и переменных окружения |
| `docs` | Архитектура, настройка, отличия и приёмка |

Личные задания, документы, история чатов, логи, граф с реальными данными, скриншоты и ключи не включены. Рабочая установка Антона этим экспортом не изменяется. Имена «Антон», «Киви», «Кокос», B24U в коде и правилах — обозначения исходного сценария, а не обязательные компоненты новой системы. Значения моделей и CLI-флагов — снимок исходников, их совместимость нужно подтвердить на машине получателя.

Условия использования: можно копировать и менять наш код для собственной системы. Сторонние SDK, CLI и сервисы используются на их собственных условиях.
